Functioning Faith API

Verified scripture, chosen for the moment someone is actually in. Base URL /v1 · machine-readable index

What this API guarantees
  • text is always real scripture — from the YouVersion Platform or a word-for-word verified public-domain library. source tells you which.
  • A reference that cannot be resolved returns 404. Nothing is ever invented to fill the gap.
  • The only model-written field is note, and it is always labelled. Verse text never comes from a language model.
  • Physiological claims require real measurement. A heart-rate moment needs hr_measured: true; a resting comparison needs a real resting_hr, never an estimate.

Developer verification checklist

  1. Link a Google, Apple, or other configured identity with a provider-verified .edu email.
  2. Select your church. If it is missing, submit it; user-submitted churches remain pending until representative or manual verification.
  3. Provide a public church contact and a specific community-serving project purpose.
  4. Accept the current Developer Terms, rights standard, no-vanity standard, and accountability policy.
  5. Wait for human review. Selecting a church never proves authority to represent it.

Reports are allegations, not findings. Credentials may be revoked and a verified church contact notified only after a reviewer confirms a serious violation, records evidence, and gives the member notice. Unreviewed reports and automated scores are never sent to a church.

Getting a key after verification

Sign in to Functioning Faith, open Profile → Integrations, and use the API keys panel. Give the key a name and select Create key. It is shown once and stored only as a hash — if you lose it, rotate it. Send it as a bearer token:

curl https://faithfit-demo-production.up.railway.app/v1/scripture/Hebrews%2012:1 \
  -H "Authorization: Bearer ff_live_…"

Scopes

Rate limits

1,000 requests/hour per key; 120/hour for /moment and /rest, which reach values-aligned inference. Every response carries X-RateLimit-Remaining and X-RateLimit-Reset.

Looking up a verse

GET /v1/scripture/Isaiah%2040:31?version=206

{
  "reference": "Isaiah 40:31",
  "text": "But those who wait for Yahweh will renew their strength…",
  "source": "local",
  "version_id": 206,
  "deep_link": "https://www.bible.com/bible/206/ISA.40.31"
}

Ranges (Isaiah 40:30-31) and whole chapters (Exodus 19) work too. deep_link opens the passage in YouVersion, so your users can keep reading where they already read.

Scripture for a moment

This is the part worth integrating. Send what your app actually measured; get back the moment it classifies to and a verse chosen for it.

POST /v1/moment
{
  "elapsed_sec": 2400,
  "distance_km": 8.2,
  "total_km": 15,
  "hr": 171,
  "hr_measured": true,
  "max_hr": 190,
  "trigger": "climb_ahead",
  "grade_ahead": 6.2,
  "tradition": "evangelical",
  "seen_refs": []
}

{
  "moment": "climbing",
  "label": "Climbing",
  "measured": true,
  "zone": 4,
  "reason": "A climb ahead, around 6.2%.",
  "verse": {
    "reference": "Psalm 121:1",
    "text": "I will lift up my eyes to the hills…",
    "note": "You're climbing strong right now — let this hill remind you where your help comes from.",
    "source": "local",
    "chosen_by": "values-aligned-ai"
  }
}

Honesty rules travel with the API

  • Heart-rate-derived moments require hr_measured: true. Without it the engine classifies from time, distance and gradient, and measured comes back false — it will not infer a training zone from pace and present it as measured.
  • chosen_by is values-aligned-ai or authored, so you always know which produced the choice.
  • tradition is optional (evangelical, catholic, mainline, not_faith_specific). Omit it and nothing is assumed.

A heart rate taken at rest

For wearables and desk apps: a rate that has climbed with no movement to explain it. resting_hr is required and never estimated — elevated is a comparison, and a comparison against an invented number means nothing.

POST /v1/rest
{ "hr": 110, "hr_measured": true, "recent_hr": [109,110,111,110],
  "resting_hr": 58, "max_hr": 190, "moving": false }

{
  "context": "high_at_rest",
  "hr": 110, "resting_hr": 58, "above_resting": 52,
  "reason": "52 bpm above your resting rate of 58, with no movement to account for it.",
  "verse": { "reference": "Philippians 4:6", "text": "…", "chosen_by": "values-aligned-ai" },
  "suggested_pattern": { "key": "physiological-sigh", "name": "The double breath" }
}

What it will not do: it never tells anyone what they are feeling. A heart rate is a measurement; stress and anxiety are interpretations of one. The response gives you numbers, scripture, and a breathing pattern — the meaning belongs to your user. If you build a UI on top of this, please keep it that way.

When it declines

{ "context": null, "status": "no_baseline", "missing": "resting_hr",
  "hint": "\"Elevated\" is a comparison, and comparing to an estimate would not mean anything." }

Also no_monitor, moving (movement explains the reading), and unsettled (one spike is not a state). These are successful responses with context: null, not errors.

Errors

StatusMeaning
401Missing or unrecognised key.
403Key lacks the required scope.
404not_in_canon (the address isn't real) or unresolved (real, but no verified text available).
429Hourly budget spent. See X-RateLimit-Reset.
