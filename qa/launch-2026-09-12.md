## Current state (September 5, later pass)

Baseline moved from `4ec3c74` to `6a8bb6d`. Compilation and Web CI were checked
in that pass. Later live verification found TestFlight #139 failed; #140
successfully processed and was approved. Do not infer distribution success
from compilation or IPA creation alone.

Safety fixes in this pass, all with regression tests now running in Web CI:

- **Blocking did not end the relationship.** Every read path honoured a block,
  but `POST /users/:id/follow` had no check at all, so a blocked member could
  follow the person who blocked them back into the `followers` tier that gates
  followers-only content — or, on a private account, file a request that
  notifies the target by name. An existing mutual follow, a pending request and
  circle membership all outlived a block. `dms.block()` now severs all three
  both ways.
- **Verse threads had no block handling in either direction.** A blocked
  member's reflections stayed visible to the blocker, replying delivered the
  sender's name plus 60 characters of their own text into the blocker's
  notifications, and liking notified the author. Group pulse encouragement and
  event RSVP had the same unguarded notification.
- **Workout numbers a member submits were unbounded.** `distance_km` feeds the
  community leaderboard, challenge and journey progress, personal bests and
  stats totals; five routes wrote it, four without a ceiling, the easiest being
  a number typed into the manual-entry form. A non-numeric value was stored as
  text by SQLite and later threw on `.toFixed()` when the workout was shared to
  a DM. `duration_min`, the second ranked metric, was clamped at zero but not
  at the top.
- **Home's Notifications screen** stayed presented after a notification tap
  switched tabs, leaving Home's navigation state out of sync with its own shell.

Verified during the sweep, no change needed: age gating is consistent across
both signup paths (each rejects under-13 and applies the same private-by-default
settings for under-18); account deletion nulls the session the same way logout
does; the service worker's shell list matches `index.html`; the deferred-media
endpoint re-checks visibility on every fetch.

Open product question, deliberately not decided here: stories are filtered for
blocks but not for mutes. Mute's copy promises "their posts and workouts stay
out of your feed", which stories sit outside of. Most platforms hide a muted
member's stories. One-line change either way — it needs a decision, not a patch.

## Fixes in this batch

- Guard feed refresh/pagination with request generations so obsolete responses cannot replace another mode or append to a refreshed feed.
- Resolve Reel identity after reaction requests complete; never reuse a pre-request array index after hide/refresh.
- Apply returned like counts to Reels.
- Rank For You using metadata; load media and GPS only for authorized winners, not all 200 candidates. Response remains compatible with installed clients.
- Format home Journey progress instead of displaying raw floating-point precision.
- Update stale navigation/vertical-scroll contract checks; allow full-canon test DB initialization before authentication integration checks.
- Add executable SQLite feed tests for candidate size, media hydration, visibility, blocks, and mutes to Web CI.
- Fix deployment freshness: unchanged asset version strings plus cache-first service worker behavior kept returning old JavaScript. Bump the shell/app version and revalidate assets through HTTP validators while retaining offline fallback.

further code review moves them, and gate 6 is the one with a deadline that
cannot be compressed — Apple's review queue runs on its own clock, so the
submission date, not the code-freeze date, is what September 12 depends on.
